# Routerly Tenda compatibility

Routerly supports the Tenda brand through a model/firmware adapter registry.
Users do not choose a model manually: the local connector inspects the router's
LAN web interface and extracts only model/firmware strings explicitly exposed
by that interface.

## Detection profiles

| Profile | Detection rule | Status |
|---|---|---|
| Tenda F3 legacy V12 | Model string contains F3 and firmware matches V12.01.x | Candidate profile; must be validated on the physical F3 |
| Tenda AC10 RTL V15 | AC10 model string and V15.03.06.50 firmware | Reverse-engineered reference profile; exact hardware/firmware only |
| Other Tenda | Tenda brand detected, no exact profile match | Generic profile; all write controls remain disabled pending validation |

A detected family is not a promise that all firmware variants share an API.
Unknown, ambiguous, or partial fingerprints never enable write operations.

## Feature support

| Feature | Current status |
|---|---|
| Connected-device list | Per-profile validation required |
| Device block/unblock | AC10 reference API only; F3 remains unverified |
| Per-device speed limit | AC10 reference API only; F3 remains unverified |
| Website blocking / parental controls | AC10 reference API only; F3 remains unverified |
| Wi-Fi SSID/password | Documented AC10 setter, not live-tested; F3 unverified |
| Scheduled reboot | Documented AC10 setter, not live-tested; F3 unverified |
| Admin password change | Not implemented |
| Encrypted Private DNS (DoH/DoT) | Not verified |
| Secure VPN setup | Model/firmware dependent; PPTP is obsolete and must not be recommended |
| Cumulative usage history | Not verified; instantaneous rates are not cumulative totals |

## F3-specific notes

The F3 family uses legacy Tenda goform web handlers in some firmware lines,
but that does not prove it accepts the AC10 endpoint names, authentication
flow, or parameter formats. Public research identifies the F3 V12 firmware
family and several legacy handlers; some public disclosures also describe
serious vulnerabilities in old F3 firmware. Routerly therefore performs
read-only fingerprinting only and does not send guessed write commands to F3.

The first F3 validation should record:
- Exact hardware revision printed on the router label
- Full firmware version shown in the router admin UI
- Read-only responses for device list and system information
- The exact browser network requests generated by ordinary admin UI actions

Do not export or share admin passwords, session cookies, or WAN credentials.
Before testing, update to the latest official firmware available for the exact
hardware revision and disable WAN-side remote administration.

## Safety rules

- Router admin credentials stay in the local connector process and are not
  sent to the cloud relay or stored in browser local storage.
- Detect and display model/firmware before considering any write action.
- Never infer compatibility from the brand alone.
- Read list-valued settings before changing them; some setters replace the
  entire list.
- Require explicit confirmation for Wi-Fi changes and reboots.
- Return a truthful unsupported result rather than simulating success.
- Do not enable router port forwarding or WAN admin exposure.

## Evidence boundary

The AC10 reference adapter is based on the reverse-engineered
bluescorpian/tendactl project. A separate public Tenda test suite records
legacy goform endpoints and sample response shapes across an AC15-style
implementation; it is evidence of a related family, not proof of F3
compatibility. F3 endpoint support remains unverified until tested against
the user's exact hardware and firmware.
